# TUI audit and patch report

Reviewed baseline: `89a1a73` in MilkmanAbi/ytcui-test-repo. Date: 5 November 2026 (Singapore). C++17 remains the required language standard.

## Result and scope

This audit covers `src/tui.cpp`, `src/input.cpp`, `src/termcaps.cpp`, their headers, the App event-loop/share/settings handlers, thumbnail output, core text/QR/clipboard/process helpers, and their tests. It addresses 20 concrete rendering, input, lifecycle and compatibility findings below. It is not a formal proof of correctness or a claim that every terminal/font/profile was physically tested.

The QR fix stays inside ncurses and the normal App event loop. Apple Terminal uses font-independent cells by default: every module is two background-painted spaces wide and one terminal row high. On smaller windows, the dialog keeps the URL visible and explains the required dimensions; it never draws a clipped QR. Press `m` to choose compact half-block mode, `c` to copy, and Esc/q/Enter to close. Both axes include the entire four-module quiet zone. The standard short YouTube link needs 80 columns by 41 rows in cell mode, or 43 columns by 23 rows in compact mode for the tested short link; the dialog calculates the requirement from the actual encoded matrix.

Compact mode still depends on the terminal font/profile drawing half-block glyphs as single-width, adjoining cells. The cell mode does not use those glyphs. Apple explicitly documents that its profile can treat East Asian Ambiguous characters as wide; therefore a UTF-8 locale and libc width measurement alone do not prove the terminal's profile agrees. This is a compatibility explanation, not a claim that this particular preference was the cause on the user's Mac. [Apple Terminal profile documentation](https://support.apple.com/en-bw/guide/terminal/trmladvn/mac).

## Findings and corrections

Priorities describe user impact, not security ratings. P1 means a central operation could become unusable or terminate the process; P2 means an important correctness/compatibility defect.

| ID | Priority | Evidence in baseline | Correction |
|---|---|---|---|
| TUI-01 | P1 | `TUI::show_qr_fullscreen` calls `endwin()` then `getchar()`. Shell input may be canonical again; the App event loop, timer, IPC polling and resize processing are suspended. | Share opens a normal modal state. The App keeps running. Single-key close and resize use ordinary curses input. The blocking/raw implementation is removed. |
| TUI-02 | P1 | Fullscreen QR prints without viewport checks. The overlay checks width only, caps the panel height, then draws QR rows beyond its intended body. | The complete raster, quiet zone, dialog and footer must fit in both axes. Otherwise only the link and size guidance are displayed. |
| TUI-03 | P2 | Fullscreen rendering assumes UTF-8 half/full-block glyphs have the desired width and shape on every terminal/profile. | Apple defaults to spaces/background cells; an explicit compact-mode choice remains available. Compact is disabled if the locale/width checks fail. |
| TUI-04 | P2 | Overlay uses the theme's background and `A_REVERSE`, so contrast and polarity depend on the theme. Fullscreen ANSI output is outside curses' attribute model. | Reserved black-on-white QR pair; each cell resets inherited bold/dim/reverse attributes. The quiet zone is painted explicitly. |
| TUI-05 | P2 | `show_share_menu` claims the clipboard changed from a generic success result; overlay footer always says copied. `YTCUI_MACOS` is not defined by this build, excluding macOS-only pbcopy/open branches. | Native platform detection also uses `__APPLE__`; external clipboard tools are preferred. Copy is explicit and the dialog shows the helper's actual status. Apple Terminal is not told OSC 52 succeeded. |
| TUI-06 | P1 | Clipboard helper uses one blocking pipe write and blocking waitpid, with no deadline or SIGPIPE protection. Partial writes and a dead helper can terminate/freeze the UI. | Deadline-bounded socket stdin transport handles partial writes and early closure without SIGPIPE. Clipboard helpers do not capture daemon-owned stdout/stderr pipes. A background-owner fixture verifies prompt return. |
| TUI-07 | P2 | Width/truncation loops leave malformed multibyte decoder state unrecovered and can append nonprintable codepoints at width zero. Wrapped titles can bypass their sanitizer. | Strict UTF-8 scalar validation; shared single-line sanitizer and locale-aware clipping remove controls/bidi formatting and orphan combining marks before rendering. |
| TUI-08 | P2 | Numerous positioned printf/addstr paths write to the end of strings, allowing titles/status/prompts to wrap into adjacent rows after resizing. | All positioned text goes through bounded writers. Every output is sanitized, measured and clipped to the real screen edge. Rectangles, selection bars and thumbnail rows are bounded too. |
| TUI-09 | P2 | Modern ncurses is assumed to make `COLOR_PAIR` support IDs above 255. Thumbnail colors can alias reserved UI pair bits. | Allocation is capped by both the legacy attribute mask and 255, with QR/UI slots reserved. Remaining slots map the 256 source colors. |
| TUI-10 | P2 | Theme indices such as 214/255 are passed directly to init_pair on eight-/sixteen-color terminals, where they are invalid. Default-background support is assumed. | Map to the available palette, honor use_default_colors failure, and skip invalid/unavailable pair initialization. Monochrome selection remains usable. |
| TUI-11 | P2 | Global mouse/tab processing precedes several modal handlers; clicks can change controls underneath a popup. Several early modal handlers leave mouse reports unconsumed. | Modal routing precedes global routing. Popups own/drain events; quality selection and supported picker clicks use their visible geometry. |
| TUI-12 | P2 | Streamlined rendering omits browser, save, sort, playlist and new-playlist overlays even though their input paths are reachable. | Both layouts use the same overlay renderer. A streamlined browser-caption assertion catches this omission. |
| TUI-13 | P2 | Search input reads additional getch events synchronously with a changed timeout to assemble Unicode; fragmented input can be dropped or swallow another key. Streamlined and playlist-name input use different byte handling. | Incremental UTF-8 assembly across frames, with no nested read. Incomplete sequences do not consume the next ASCII/special key. Search and playlist limits are enforced. |
| TUI-14 | P2 | Fixed popup widths and raw selection/rectangle writes extend beyond narrow or short windows. | Quality dialog adapts to width; small windows have a bounded fallback. Resize is not interpreted as a modal command. |
| TUI-15 | P2 | Several direct vector lookups reject high indices but not negative indices; negative result/quality/action scroll can index before a container. | Validate both bounds and clamp derived scroll positions. Tests deliberately supply stale/negative selections. This is defensive state hardening; a live-input crash was not claimed. |
| TUI-16 | P2 | Raster images are flushed after popup text and can cover the popup. Kitty placements are not cleared when switching away from Kitty or shutting down. | Popups discard underlying graphics; old Kitty placements are deleted on mode changes and shutdown. |
| TUI-17 | P2 | TUI changes flow-control flags without explicitly owning/restoring its original terminal state; screen structures are not explicitly released. | Save original termios before initialization, own newterm's SCREEN, disable mouse during cleanup, call endwin/delscreen and restore the saved flags. Initialization can fail without calling initscr's fatal path. |
| TUI-18 | P2 | Hard-coded 25 ms escape delay overrides user settings and is aggressive for SSH/fragmented key sequences. | Respect ESCDELAY; use a modest 100 ms default only when no override was supplied. |
| TUI-19 | P2 | Add-to-playlist picker displays only its first rows even when keyboard selection moves below them. | Visible playlist/browser rows scroll with the selected entry; mouse geometry uses the same offset. |
| TUI-20 | P2 | Detection can retain stale state across calls, overwrite a multiplexer identity with the outer Apple terminal, or upgrade Apple/Linux console to truecolor from inherited COLORTERM. Apple startup sends unnecessary queries and drains input. | Reset capability state, preserve multiplexer identity, constrain known color limits and skip queries on Apple Terminal. Other probe reads now have a monotonic deadline and response-size bound. |

The color-pair issue is an API distinction: extended initialization does not make the legacy attribute macro carry extra bits. [ncurses attribute documentation](https://www.invisible-island.net/ncurses/man/curs_attr.3x.html).

The QR margin is not cosmetic: all four sides must retain the four-module quiet zone. [DENSO WAVE QR documentation](https://www.qrcode.com/en/howto/code.html).

The resize strategy keeps curses responsible for its window-size notifications and consumes KEY_RESIZE before modal actions. [ncurses resize documentation](https://invisible-island.net/ncurses/man/resizeterm.3x.html).

## Additional maintenance in this patch

- Cache the encoded QR per URL while its dialog is open.
- Keep full-cell mode independent of Unicode block-font coverage; do not replace a clipped QR with a partially drawn symbol.
- Replace remaining progress-bar ACS glyphs with the application's normal border/ASCII paths.
- Settings key capture no longer binds a pending mouse-report token as an accelerator.
- Preserve C++17 and the compiler guard against accidental C++20-only syntax.

## Validation

The new `test_tui` exercises text, incremental input, transport, native-tool selection, capability resetting, modal isolation, screen bounds and QR colors. Its rendering matrix covers seven terminal sizes, normal/streamlined UI, six streamlined screens, eight focus/overlay states, three themes (including strict monochrome), and three terminfo profiles: 6,048 rendering scenarios. These are headless curses cell tests, not screenshots of three physical terminal emulators.

QR raster tests reconstruct every original module from both rendering modes. A separate ZXing-C++ decoder successfully decoded a grayscale image captured from the actual colored ncurses QR cells to the intended short YouTube URL. This independently checks the paint polarity/geometry, not just the source matrix.

Clipboard tests use private fake tools and synthetic text. No system clipboard or user browser data is accessed by those tests. They include partial input, immediate closure, a non-reading child, and a helper that forks a background owner.

Final build, sanitizer and PTY results are recorded after completion below. GitHub CI remains the platform/compiler check; a local Linux run does not establish native macOS execution.

## Limits and follow-up

- No physical Mac/Terminal.app was available in this Windows/WSL workspace. The Mac-specific fix is based on source review, Apple documentation, font-independent rendering, and simulated terminal capabilities. A real Terminal.app scan remains the final visual/device check.
- Arbitrary fonts, line spacing, application color remapping and unusual physical cell aspect ratios can still affect scanning. Cell mode eliminates block-glyph gaps/ambiguous widths but cannot calibrate an arbitrary font's cell aspect ratio.
- Complex emoji/grapheme presentation remains constrained by curses/libc width tables. The safe writer deliberately removes terminal-dependent joiners/selectors; it does not claim full Unicode grapheme shaping.
- Non-Apple startup capability probes still have a short input-drain window. Apple avoids it entirely in this patch. A full terminal-response/keyboard demultiplexer is separate work.
- A clipboard helper reporting success is the available OS-tool contract; OSC 52 still has no clipboard-write acknowledgement and is reported as a send operation, not a verified clipboard change.

## Final local results

- Full GCC 13.3 Debug build: zero compiler warnings/errors; all 14 CTest tests passed, none skipped.
- AddressSanitizer: runtime/storage, App lifetime/share opening, and TUI suites all passed (3/3), with no sanitizer errors.
- The TUI test completed all 6,048 render scenarios plus input, clipboard, geometry and QR assertions, including the complete compact QR at 80×24.
- Real PTY: resize notification handled; one q byte closed the share view without Enter; original terminal flags restored; successful exit in approximately 0.82 seconds.
- ZXing-C++ independently decoded the QR captured from the ncurses cells to `https://youtu.be/jNQXAC9IVRw`.
- actionlint validated the CI workflow, including the added TUI sanitizer target.

The QR capture is a test-render artifact, not a screenshot of Terminal.app. Native Mac visual/font validation is still needed; no claim of a physical Terminal.app test is made.
